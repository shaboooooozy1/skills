# Edit Mode

Use when the user pastes their own draft. The draft's facts, names, numbers, and ask belong to the user. Change the prose. Keep the substance.

## Pass order

Run the passes in this order. Each one makes the next easier.

1. **Find the ask.** Name the one action the reader must take. If there are several, keep the most important and move the rest to a follow-up note for the user. If there is none, flag it.
2. **Find the problem.** Locate the sentence about the reader's risk, exposure, or deadline. Move it to the top.
3. **Cut.** Delete throat-clearing, credentials paragraphs, restated context, "I think," "I believe," "just," "really," "very."
4. **Split.** Break any sentence with a comma splice, semicolon, or more than one idea.
5. **Sharpen.** Replace adjectives with numbers and dates the draft already contains. Never invent a figure. Use `[confirm figure]` if a claim needs one the user did not give.
6. **Close.** Rewrite the last line as one specific ask with a date or two time options.
7. **Audit.** Run the Voice DNA checks and the anti-pattern list in SKILL.md.

## Gaps to flag, not fill

Flag these for the user above the revision, in one line each:

- The reader would ask "why now?" and the draft does not say.
- A deadline, quote expiry, or renewal date is implied but missing.
- A coverage statement reads as a promise ("you're covered for..."). Suggest neutral wording.
- An attachment is referenced but the draft does not say what it contains.

## Common requests

| User says | Do this |
|---|---|
| "Shorter" | Target half the word count. Keep the problem, the proof, and the ask. |
| "Too harsh" / "softer" | Keep the declarative structure. Add one line of genuine acknowledgment (their time, the relationship, a past result). Do not add hedges. |
| "Too soft" / "stronger" | Remove qualifiers. Lead with the number. End on the ask. |
| "Subject line" | Give three options, each under 8 words. One names the risk, one names the date, one names the reader's company or topic. |
| "Check the tone" | Return a two-line verdict first, then the revision. |

## Output format

1. One line: what changed and why (only if the change is structural).
2. Any flagged gaps, one line each.
3. The revised message, ready to paste. Subject line first if it is an email.

## Example

**Draft:**
> Hi Tom, I hope you're doing well! I just wanted to reach out and touch base about your upcoming renewal, which I believe is coming up sometime in the next couple of months. We've been seeing some changes in the market and I think it might be a good idea for us to find some time to connect and go over everything. Let me know when works for you!

**Revision:**
> Subject: Your [renewal date] Renewal – What Changed
>
> Tom,
>
> Your program renews [renewal date]. The market moved since last year. Some of it affects your premium.
>
> I have your file open and a recommendation ready.
>
> Does Tuesday at 10:00 or Thursday at 2:00 work for 20 minutes?

Flagged: the draft gives no renewal date. Fill it in before sending. Naming one specific market change would make the case to meet stronger.
